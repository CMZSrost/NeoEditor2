## 1. 三种用户画像审视

### 1.1 新人：刚读完模组制作指南

**目标**：创建第一个简单 Mod（加一件物品、改一个配方）。

#### 做得好的

| 功能 | 说明 |
|------|------|
| 字段帮助 Tooltip | 列头悬停显示 `[Comment]` 中文说明——这是新人最需要的功能 |
| 引用显示为名称 | `nFaction=1` 显示为 `Dogman (id=1)`，不用手动查表 |
| 类型适配编辑器 | bool→CheckBox、Enum→ComboBox、longtext→多行——防止格式错误 |
| 行增删 | 工具栏 `+` `-` 按钮，Clone Row 复制模板 |
| Undo/Redo | Ctrl+Z/Y 降低试错成本 |
| 数据验证框架 | `Data/Validation/` 代码已存在（引用完整性、必填、值域检查）⚠️ 但未接入保存流程 |

#### 做得不好的

| 问题 | 严重度 | 说明 |
|------|:------:|------|
| **向导缺失** | 🔴 | 没有 "Add New Item" 向导；不知道 ItemType 需要配 TreasureTable + Condition 才能用 |
| **Save 语义混乱** | 🔴 | 单 Mod 视图点"保存"只写数据库，不写 XML。新人不知道还要再点"Export XML" |
| **Import → Load 两段式** | 🟡 | 导入 Mod 后还要点 Load 按钮。虽然首次 Import 自动 Load，但 UI 上有两个按钮让新人困惑 |
| **无行内验证** | 🟡 | 输入非法值不报错，默默写入。验证框架已存在但未接入——代码白写 |
| **概念门槛** | 🟡 | AddRow 对话框要求理解 Target Mod（Insert vs Merge）、Target XML 路径、Key ID 分配 |
| **入门文档脱节** | 🟡 | docx 指南和编辑器之间没有桥接——无法从编辑器内打开对应字段的帮助 |

### 1.2 老手：用文本编辑器开发多年

**目标**：高效编辑，编辑器必须提供文本编辑器做不到的价值。

#### 做得好的——"文本编辑器做不到的事"

| 功能 | 说明 |
|------|------|
| 合并视图 + 覆盖链可视化 | 看到 Mod 层层叠加的效果，文本编辑器完全做不到 |
| 跨表引用导航 | Ctrl+Click 跳转到目标实体，不用手动查 ID |
| 查找替换（正则/全词/大小写） | 字段级匹配 + 单元格高亮 |
| 可视化编辑器 | Recipe 树、Story Graph、TreasureTable 树——关系一目了然 |
| Clone Row | 最快的方式创建相似实体 |
| CSV 导入导出 | 批量操作能力 |

#### 做得不好的——"文本编辑器更快的事"

| 问题 | 严重度 | 说明 |
|------|:------:|------|
| **不能直接编辑 XML** | 🔴 | 老手习惯 Notepad++ 打开 `neogame.xml` 直接改。编辑器要求 Import → 点开 DataGrid → 编辑 → Save → Export XML，多了 3 步 |
| **Import 步骤是纯摩擦** | 🔴 | 老手已经有了 XML 文件，导入步骤没有任何价值——它只是把 XML 解析到 DB。如果编辑器能直接打开 XML 进入编辑模式，一步到位 |
| **列复制粘贴不支持** | 🟡 | Excel 式的列间复制粘贴是批量操作的标准方式，目前只能逐个单元格编辑 |
| **Save 不写磁盘** | 🟡 | 单 Mod 模式下"保存"不到 XML，老手改完去游戏测试发现没生效——破坏信任 |
| **没有 Ctrl+S** | 🟡 | 老手的肌肉记忆：Ctrl+S = 保存到文件。目前 Ctrl+S 没有绑定 |
| **打开 Mod 路径间接** | 🟡 | 右键 → ShowData → 在 DataGrid 编辑。vs 文本编辑器：双击 XML 文件 |
| **无多行批量编辑** | 🟡 | 选中 50 个 ItemType 想把 `fWeight` 改成 0——要逐个改 |

### 1.3 整合包作者：需要合并多个 Mod

**目标**：将 5-20 个 Mod 合并，处理覆盖/冲突，发布整合包。

#### 做得好的

| 功能 | 说明 |
|------|------|
| 合并视图 | 所有 Mod 按 load order 合并展示——核心需求满足 |
| 覆盖链面板 | 选中行显示该实体在各 Mod 中的版本链 |
| 字段级来源标记 | Cell ToolTip 显示"这个值来自哪个 Mod" |
| 冲突检测 | `⚠ CONFLICT` 标记两 Mod 改同一字段 |
| Show All 切换 | 查看被覆盖的败者实体 |
| 保存回落源 Mod | 合并视图编辑后自动写回源 Mod XML |
| Mod 过滤 ComboBox | 合并视图快速筛选只看某个 Mod 的数据 |
| Profile 对比 | 两个 Profile 的 Mod 列表差异对比 |

#### 做得不好的

| 问题 | 严重度 | 说明 |
|------|:------:|------|
| **无 Mod 依赖分析** | 🔴 | 整合 10 个 Mod 时不知道 A 引用了 B 的 Creature，但 B 排在 A 后面 |
| **无冲突汇总报告** | 🔴 | 只能逐行看 Tooltip 找冲突，没有"这个 Profile 总共 42 个冲突"的汇总视图 |
| **无"每个 Mod 贡献了什么"报告** | 🟡 | 整合包作者需要知道：NSE Mod 覆盖了哪些实体、新增了哪些 |
| **Load Order 不可视化** | 🟡 | 合并视图显示结果，但看不出加载顺序——哪个 Mod 先加载、哪个后加载是隐式的 |
| **Profile 切换不联动** | 🟡 | 切换 Profile 只更新 Profile 面板，已打开的合并视图不会自动刷新 |
| **无批量冲突解决** | 🟡 | 42 个冲突要逐个手动处理——没有"全部采用 Mod A 的值"这类批量操作 |

## 2. 当前编辑器工作流

### 2.1 单 Mod 编辑完整路径

```
┌──────────┐    ┌──────────┐    ┌──────────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 导入Mod   │───→│ 加载到DB  │───→│ 双击打开      │───→│ 编辑单元格  │───→│ 点 Save  │───→│ 点Export │
│ 选文件夹   │    │ (自动)    │    │ DataGrid     │    │ +/- 行     │    │ (写DB)   │    │ (写XML)  │
└──────────┘    └──────────┘    └──────────────┘    └──────────┘    └──────────┘    └──────────┘
     1              2                  3                 4               5               6
```

**步骤 1-2**（导入 → 加载）：首次导入自动完成。如果用户在编辑器外改了 XML 文件，需要手动点 Load 重载。

**步骤 5-6**（Save → Export XML）：这是最大的用户困惑点。Save 只写数据库——新人和老手都以为"保存"代表写入文件。

### 2.2 合并视图编辑路径

```
┌──────────┐    ┌──────────┐    ┌──────────────┐    ┌──────────┐    ┌──────────┐
│ 导入所有Mod│───→│ 创建Profile│───→│ 右键→打开    │───→│ 编辑合并   │───→│ 点 Save  │
│ (逐个)    │    │ getmods.php│    │ 合并视图     │    │ 视图      │    │ (DB+XML) │
└──────────┘    └──────────┘    └──────────────┘    └──────────┘    └──────────┘
     1              2                  3                 4               5
```

**步骤 1** 最耗时：每个 Mod 都要手动导入，没有批量导入。

**步骤 2**：导入 getmods.php 或手动创建。如果 Profile 引用了尚未导入的 Mod，编辑器不会提示。

**步骤 5**：合并视图 Save = DB + 自动 Export XML。这个行为与单 Mod 不一致但实际更正确。

### 2.3 工作流断裂点

| # | 断裂点 | 影响 | 用户群 |
|---|--------|------|:------:|
| 1 | **Save ≠ 写磁盘**（单 Mod 模式） | 用户改完数据去游戏测试发现没生效 | 新人、老手 |
| 2 | **必须先 Import 才能编辑** | 老手抱着 XML 文件想直接改，却被要求先走导入流程 | 老手 |
| 3 | **合并视图打开 → 单 Mod 全部只读** | 用户困惑为什么之前的编辑标签页突然不能改了 | 新人、老手 |
| 4 | **没有快捷入口打开合并视图** | 整合包作者每次要右键 Profile → 菜单，多步操作 | 整合包 |
| 5 | **DB 是中间状态，用户看不到** | Save 后数据"在哪"不透明——DB 对用户是黑盒 | 所有人 |
| 6 | **Profile 切换与视图脱节** | 切换了 Profile，合并视图不自动刷新 | 整合包 |
| 7 | **没有 Ctrl+S 快捷键** | 肌肉记忆失效 | 老手 |
| 8 | **Load Mod 按钮名字误导** | "Load" 听起来像"加载"，实际是"重新解析 XML 到 DB" | 新人 |

## 3. 关键问题清单

### 3.1 架构层面

#### P0: Save 语义统一

**现状**：单 Mod `Save` = 只写 DB；合并视图 `Save` = 写 DB + 自动 Export XML。

**修复方向**：统一为 Save = DB + 写 XML。去掉 Export XML 独立按钮（或降格为高级菜单项）。Save 按钮应明确：点击即持久化到磁盘。

#### P0: 直接打开 XML 编辑（跳过 Import）

**现状**：老手用户被迫走 Import → Load → 打开 DataGrid 的路径。

**修复方向**：提供 "Open XML File" 入口，直接选择 XML 文件或 Mod 文件夹，一次性完成：创建 ModInfo（如不存在）→ 解析到 DB → 打开 DataGrid。让老手感觉就像"双击 XML 文件"一样快。

#### P0: Ctrl+S 快捷键

**现状**：保存无键盘快捷键。老手用户反复触发鼠标操作。

**修复方向**：在 `ModGameDataTabsView` 注册 `Ctrl+S` 全局快捷键 → 触发 Save。

#### P1: 合并视图冲突汇总

**现状**：`FieldConflicts` 数据已存在，但只用于 Cell ToolTip 显示。用户无法获取"总共多少冲突"的全局视角。

**修复方向**：合并视图工具栏新增冲突指示器："⚠ 42 conflicts"，点击弹出 ConflictsPanel 列出所有冲突（表名、字段、冲突 Mod），支持批量解决。

#### P1: 数据验证接入保存流程

**现状**：`Data/Validation/` 有引用完整性、必填、值域规则，但未接入保存。代码资产闲置。

**修复方向**：保存时运行验证，以 **Warning（不阻止）** 模式报告，范围限定当前 Mod。验证报告展示后用户可选择忽略或跳转修复。

### 3.2 UI/UX 层面

#### P1: Import 流程简化

**现状**：ModDatabase 面板有 Import、Load、LoadAll 等多个按钮，功能重叠。

**修复方向**：
- Import 按钮 = 选文件夹 → 注册 + 首次加载 → 自动打开 DataGrid（一步到位）
- 移除单独的 Load/LoadAll 按钮，改为右键菜单 "Reload from Disk"（仅高级场景需要）
- Mod 列表项显示状态图标：✓ 已加载 / ⬜ 未加载

#### P1: 合并视图入口优化

**现状**：必须通过 Profile 面板右键菜单打开，路径深。

**修复方向**：
- Profile 列表项双击 = 打开合并视图（最快捷入口）
- 工具栏新增 "Merge View" 下拉按钮显示活跃 Profile 列表
- 如果只有一个 Profile 且没有合并视图打开，启动时自动提示

#### P2: 标签页脏标记视觉强化

**现状**：`Header` 加 `*` 后缀表示有未保存修改。

**修复方向**：用颜色标记（橙色/红色文字）+ 关闭时有明确提示 "当前标签页有未保存修改，是否保存？"

#### P2: 工具栏按钮重新布局

**现状**：`[←] [+] [-] [status] [Show All] [Save] [Export]`。

**修复方向**：
```
主工具栏:  [← 返回] [+] [-] [🔍过滤框] [Show All ☐] [💾 Save]  [冲突指示器: ⚠ 42]
右键菜单:  Clone Row | Find References | Export XML | ...
```

### 3.3 功能完整性

#### P0: Mod 依赖分析

**现状**：完全没有。整合包作者不知道 A Mod 引用了 B Mod 的实体。

**修复方向**：
- 在合并视图加载后运行：扫描所有 `[ReferenceField]` → 检查引用目标是否存在 → 生成报告
- 三种依赖问题：
  1. **缺失引用**：引用的实体在所有 Mod 中都不存在
  2. **跨 Mod 引用**：引用 B Mod 的实体，但 B 不在当前 Profile 中
  3. **加载顺序问题**：引用了 B 的实体，但 B 在链中排在 A 之后（Insert 空间实体不参与覆盖）

#### P1: Mod 贡献度报告

**整合包作者需要知道"每个 Mod 贡献了什么"**：
- 新增了多少实体（Insert 空间）
- 覆盖了多少实体（Merge 空间）
- 引入了多少冲突
- 一键导出为 Markdown/CSV

#### P2: 多行批量编辑

**选中多行 → 右键 → "Edit Selected..." → 选择目标字段 → 输入新值 → Apply**。

#### P2: 列复制粘贴

**Excel 式 Ctrl+C 复制单元格内容，Ctrl+V 粘贴到其他行同列**。

## 5. 理想工作流（目标状态）

### 新人创建一个新物品

```
双击桌面图标
  → 主界面自动打开上次的 Mod
  → 点击 + 按钮 → AddRowDialog（简化版：有模板可选）
      → 选 "New Item" 模板
      → 填写名称、重量 → 确定
  → DataGrid 自动定位到新行
  → 右侧 ItemType 可视化编辑器显示物品预览
  → 引用字段（nTreasureID）下拉框列出可选 TreasureTable
  → 按 Ctrl+S 保存
  → 保存前显示验证报告："nTreasureID 引用的 TreasureTable #99 不存在"
  → 用户修复后再次 Ctrl+S → 成功 → 通知"已写入 neogame.xml"
```

### 老手批量修改

```
打开编辑器 → Ctrl+O 选择 XML 文件（或直接拖拽 XML 到窗口）
  → 自动识别 Mod → 打开 DataGrid
  → 选中 50 行 → 右键 "Edit Selected"
  → 选 fWeight → 输入 0 → Apply
  → Ctrl+S → 完成
```

### 整合包作者合并 Mod

```
双击 Profile "MyPack" → 打开合并视图
  → 工具栏显示 "⚠ 42 conflicts" 
  → 点击冲突指示器 → 弹出冲突列表
  → 按 "采用 Mod A 的值" 批量解决
  → 依赖分析自动运行："Warning: NSE Mod 引用了 Creature #15，但该实体在后续 Mod 中被覆盖"
  → Save → 所有源 Mod XML 更新
  → "Export Mod Pack" → 一键打包 .zip
```
