## 1. 外部 "N dirty" 计数 = 实体数（追修 1）

**前置**：打开一个 mod 的数据表，编辑 **3 个不同实体**（如改 3 行的 strName），等自动保存（~1s）。

- [ ] **1.4** 保存并导出（Ctrl+Shift+S）确认后：以上计数全部归零。

## 2. 字段级 dirty：只标改动字段（追修 2）

**前置**：工作区打开，任选一行实体。

- [ ] **2.1** DataGrid 改一个字段（如 `strName`）→ 仅该**单元格**变黄 + **主键单元格**变黄（锚点），**其他单元格不变**（不再是整行黄）。
- [ ] **2.2** 再改第二个字段（如 `fDamageBlunt`）→ 只有这两个单元格 + 主键亮。
- [ ] **2.3** Value Editor（Left KV）：编辑一个字段 → 只有该字段显示黄色 ●（"已修改未导出"），其他字段不亮。
- [ ] **2.4** 自动保存后高亮保留；Save & Export 后全部清除。
- [ ] **2.5** 新建实体 → 整行绿；Merge 覆盖行整行灰（行级保留）。

## 3. 旧标记升级 + 加载校验（追修 3 + 用户建议）

## 7. 多 profile 隔离（B+C 核心）

**前置**：profile A 与 profile B 都包含**同一个 mod X**（可先复制 profile 或新建）。

### 7.1 WAL 隔离（B）
- [ ] **7.1.1** 在 profile A 编辑实体 E（改 strName）→ 切到 profile B 打开同一 mod：**不出现 A 的编辑**（值保持基线），也不显示 A 的 dirty。
- [ ] **7.1.2** 切回 profile A：编辑仍在（dirty 恢复）。
- [ ] **7.1.3** 重启应用 → profile A 的编辑恢复（WAL 按 profile 隔离，不串到 B）。

### 7.2 覆盖层保存（C）
- [ ] **7.2.1** profile A 编辑实体 E → 自动保存 → **game.db 实体表不变**（基线未被写），编辑只进覆盖层。
- [ ] **7.2.2** profile B 编辑**同一实体 E 的不同列** → 保存 → A 的列覆盖与 B 的列覆盖**共存**（互不覆盖）。
- [ ] **7.2.3** profile B 编辑同一实体 E 的**同一列** → 各自保存 → 各自视图显示各自的值（互不影响）。

### 7.3 新建 / 删除
- [ ] **7.3.1** profile A 新建实体 → 自动保存 → 切 B：**B 看不到**该实体；切回 A：实体还在（绿）。
- [ ] **7.3.2** profile A 删除实体 → 保存 → 切 B：实体**仍在**（基线未删）；切回 A：实体已删。
- [ ] **7.3.3** 重启后 A 的新建/删除状态恢复。

### 7.4 导出
- [ ] **7.4.1** profile A Save & Export → 导出的 XML 含 A 的编辑（含新建实体、不含已删实体）。
- [ ] **7.4.2** 导出后 A 的覆盖层清空（dirty/高亮归零）；**B 的覆盖层不受影响**（B 的编辑还在）。
- [ ] **7.4.3** 导出后再次打开 A：实体表=导出状态（基线推进），无残留标记。

### 7.5 Discard（MCP/CLI 或视图）
- [ ] **7.5.1** 编辑后 Discard → dirty 清空 **且重启后编辑不复活**（覆盖层已清）。

## 已知边界（验收时注意，非缺陷）

- 游戏基础数据（ModId=-1）编辑仍走 `("game", 0)` 共享 WAL（merge editor 聚合场景为主），不参与 profile 隔离。
- 实体表现在是**共享基线**（导入/导出写入）；各 profile 的编辑在 `profile_edits` 覆盖层——直接查看 game.db 看不到未导出的编辑（属预期）。
- 旧库中已保存过的编辑（实体表现状）固化为基线；仅"编辑后未导出"的差异走覆盖层。
- HomePage 实体计数（ModEntityStats）读基线，新建实体未计入统计（展示误差，非数据问题）。
