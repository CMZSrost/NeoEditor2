# [R00] spec 的维护规则（元规则）

| 字段 | 内容 |
|------|------|
| **是否启用** | ✅ 生效 |
| **类型** | 基石(DO) |
| **创建来源** | 用户指示 / 2026-06-29 |
| **创建时间** | 2026-06-29 |

**是什么**
> `spec/` 用增量方式维护决策规则：
> 1. 一文件一规则，文件名 `R0X-简述.md`（基石/DO）或 `N0X-简述.md`（禁止/DON'T）。
> 2. 每条规则必须含模板六项：标题、是否启用、类型、创建来源、创建时间、（是什么/为什么/决策边界）。
> 3. **只增不改**：已生效规则不就地改语义；要变更则新建一条，并把旧条「是否启用」置为 ⛔ 废弃，注明被谁取代。
> 4. 待拍板的决策放 [open-questions.md](open-questions.md)，确认后转为正式规则文件。
> 5. 新增/废弃规则后，更新 [README.md](README.md) 登记表与根 [../index.md](../index.md)。

**为什么**
> 规则是开发的硬约束，必须可追溯、可审计。增量+只增不改保证历史完整，避免规则被悄悄改写。

**决策边界**
> 适用：`spec/` 下所有文件的创建与维护。
> 例外：错别字/链接修正等不改变语义的编辑可直接改。
> 相关：[_template.md](_template.md) 模板；[README.md](README.md) 登记表。
