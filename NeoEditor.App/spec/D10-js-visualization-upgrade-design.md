## 〇、背景与定位

**审查结论**（AF4 全量审视 24 个实体 visualizer）：**内容语义层已成熟**——心理模型翻译
（`90.1x1=12x1x0x0x0` → `🛡 撬棍 ×1 →`）、渐进式展开、少呈现、语义色一致、peek/tooltip
体贴细节，D04-D08 全部落实。系统性缺口集中在四件事：

| # | 缺口 | AF4 依据 | 对应改进 |
|---|------|---------|---------|
| 1 | **导航与寻路**：Ctrl+Click 跨文档跳转无返回，引用网漫游会迷失 | ch11 流 / ch12 记忆负担 | §3.1 |
| 2 | **软件记忆力**：滚动位置、展开状态在重渲染后归零 | ch08 记忆力 | §3.2 |
| 3 | **视觉一致性**：SectionHeader（3 类型）与旧 SectionLabel 灰字（21 类型）双轨 | ch17 一致性 | §3.4 |
| 4 | **信息层级**：Raw Data 审计面板永远压在最顶部，展开即把 Hero 推下屏 | ch17 答案优先 / ch14 审核不抢主视觉 | §3.3 |

**定位（本设计是什么）**：
1. 是 **JS 组件升级的设计思路**（D09 §四「UI 规格迁移」的补充规格），随 D09 P1-P4 实施；
   **不在 Avalonia 层做改造**（D09 v1.1 决策：P4 验收后下线 Avalonia visualizer，不留双轨）；
2. **不改变 D04-D08 的语义规格**——语义翻译、节点卡语言、效果区聚合等全部原样继承，
   本设计只增加**组件层/交互层**的统一与改进；
3. 修订一处 Avalonia 层既有约束：21-guide 规则 3「Raw Data 必须在最顶部」→ 移页面底部，
   **只对 JS 版生效**。

## 一、设计原则（AF4 锚点）

| # | 原则 | AF4 依据 | 状态 |
|---|------|---------|------|
| 1 | 页面回答问题，不罗列字段 | ch01 三种模型（贴心理模型）/ ch03 目标 | ✅ 已有，保持 |
| 2 | 消灭负担：导航标志 / 软件记忆力 / 少呈现 | ch12 | ★ 本设计新增重点 |
| 3 | 一套组件库，无双轨 | ch17 一致性（眯眼测试） | ★ 本设计新增重点 |
| 4 | 渐进式展开（常用前置、深藏靠后、折叠兜底） | ch10 | ✅ 已有，保持 |
| 5 | 可点击性可感知（顺从 + 动态提示） | ch13 | ★ 本设计新增重点 |

**人物模型锚点**：NeoScavenger mod 开发者 = 典型**永久中级用户**（ch10）——非常聪明但很忙，
不记原始语法、需要跨表引用漫游、修改前必须评估影响。可视化的三个问题：这是什么 →
它多强/值多少 → 改了它影响什么（D04/D05/D08 已按此组织，本设计补充"漫游不迷路 + 状态不丢"）。

## 二、统一页面模板（JS 组件规格）

```
┌─ body（唯一垂直滚动容器）──────────────────────────────────┐
│ ┌─ TopBar（页面级工具条，sticky）────────────────────────┐ │
│ │  ← 返回 · [类型名] · 📂 加载 XML · 审计统计 N·M·K      │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌─ Hero（统一身份区）────────────────────────────────────┐ │
│ │  图 132px │ ID · 类型 · 旗标徽章行                      │ │
│ │          │ 名称（18px Bold）                           │ │
│ │          │ 副文本（斜体灰）· 关键数字行                  │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌─ 问题区 N（两列并置，Section 组件）─────────────────────┐ │
│ │  Section(⚔ …)          │ Section(🧬 …)                │ │
│ │  Section(🎁 …)          │ Section(📍 …)                │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌─ RefPanel（反向引用·聚合摘要）──────────────────────────┐ │
│ │  被 3 个生物 · 5 个物品 · 2 个剧情引用  [过滤框]         │ │
│ │  ▸ 生物（3）  狗人 / 掠夺者 / …                        │ │
│ └───────────────────────────────────────────────────────┘ │
│ ┌─ 原始 XML（Details 折叠，页面底部）─────────────────────┐ │
└───────────────────────────────────────────────────────────┘
```

**组件清单**（新增/增强列；D09 §四 既有 Card / Section / ValueRow / StatBar / Badge /
NodeCard / RefBadge / Details 全部保留）：

| 组件 | 说明 | 取代 / 来源 |
|------|------|------------|
| `Section` | 统一区块头：图标 + 色条 + 标题 + 计数徽章 + 右侧操作区（可选 collapsible / sticky） | R40 SectionHeader 全量推广，**取代旧 SectionLabel 灰字**（§3.4） |
| `Hero` | 统一身份区（图 / 徽章行 / 名称 / 副文本 / 关键数字行） | 21-guide §二 组件化 |
| `TopBar` | 页面级工具条（← 返回 / 加载 XML / 审计统计 N·M·K） | 本设计 §3.1 / §3.3 |
| `RefPanel` | 反向引用：聚合摘要 + 过滤 + 类型分组展开 + 滚动加载 | 取代分页平铺列表（§3.6） |
| `ValueGrid` | 通用键值字段卡 | 21-guide BuildStatCard（薄类型模板主力） |
| `Badge`（增强） | `data-nav` 统一 hover 态（描边 + 抬升）+ 静态 `↗` 角标 | 本设计 §3.7 |
| `Details`（增强） | 原始 XML 折叠，位置 = 页面底部 | 本设计 §3.3 |

**模板规则**：
1. 页面结构恒为 `TopBar → Hero → 问题区 → RefPanel → 原始 XML`；
2. 区块恒用 `Section`（代码评审禁止灰字小标题直出）；
3. **垂直滚动唯一（body）**，内嵌组件只允许横向滚动（Encounter 流转三行、图片画廊）；
4. 空区块不渲染（延续 D05/D08 少呈现）；
5. 薄类型（§四 D 级）直接由模板组合，不手写渲染器。

## 三、系统改进清单（9 项）

### 3.1 导航历史（← 返回）
- **现状**：Ctrl+Click 跨文档跳转只有前进没有返回；Encounter 流转区有组件内「⏎ 回到当前」
  （D08 v1.3），是全库唯一例外。
- **AF4**：ch11 流（交互不打断即合格）/ ch12 记忆负担（用户被迫记住来路）/
  ch15（导航是探索工具）。
- **JS 设计**：
  - **组件内导航**（Encounter 流转漫游、战利品树展开等）→ 页面自持导航栈
    （sessionStorage `jsv:hist:{docId}`），TopBar「← 返回」逐级回退**重渲染**，不重新 fetch；
  - **跨文档导航** → 宿主行为不变（开新文档），JS 侧 `history.pushState(type,id)` 记录；
    后退手势 / popstate → `/viz/action {kind:'navigateBack'}` 宿主回退文档（P4 可选，
    宿主侧需导航历史）。
- **验收**：A→B→C 后点「← 返回」回到 B；Encounter 漫游 5 跳后返回不重载数据。
- **落点**：P2（组件内）/ P4 可选（文档级）。

### 3.2 状态记忆（软件记忆力）
- **现状**：文档重建 / 实体重渲染后，滚动位置、展开的攻击行与战利品树全部归零。
- **AF4**：ch08「软件记忆力：预测 = 记住上次做了什么」——每次归零都是重复劳动。
- **JS 设计**：`sessionStorage['jsv:ui:'+type+':'+id] = {scrollY, expanded[], flowFocus}`；
  scroll debounce 500ms 存储；实体重渲染（XML 编辑 → 快照刷新）只替换**内容区 DOM**
  （D09 P0.6 局部重渲染模型延伸：状态 DOM 与内容 DOM 分离）。
- **验收**：展开攻击行 → 切 XML 编辑 → 回 JS Tab：展开状态 + 滚动位置保留。
- **落点**：P2 起步（局部重渲染延伸），P4 收尾。

### 3.3 Raw Data 移页面底部
- **现状**：24 个 visualizer 的第一个子元素全是 `BuildRawData`（如
  `GameVarEntityVisualizer.cs:37`、`CreatureSourceEntityVisualizer.cs:46`；21-guide 规则 3
  明确要求"Raw Data 必须在最顶部"）——审计工具压在主内容（Hero）之前，展开即推下屏。
- **AF4**：ch17 信息层级（答案优先，兜底靠后）/ ch14（审核视图不抢占主视觉）。
- **JS 设计**：页面底部「原始 XML」Details（rawXml 快照兜底）；审计统计
  （`N 字段 · M 有值 · K 未解析`）上移到 TopBar 右侧——审计入口保留，位置让位。
- **验收**：首屏（眯眼测试）= Hero；展开原始 XML 不挤占主内容。
- **落点**：P1 模板定型时。

### 3.4 Section 组件统一（根治双轨）
- **现状**：只有 Creature / ItemType / Encounter 用 R40 `SectionHeader`（图标+色条+徽章），
  其余 21 个类型用旧灰字 `SectionLabel`（如 `GameVarEntityVisualizer.cs:74`、
  `CreatureSourceEntityVisualizer.cs:106`）——同一应用两套区块标题视觉重量。
- **AF4**：ch17 一致性（眯眼测试下区块层级感必须统一）。
- **JS 设计**：`Section` 唯一组件；全 24 类型渲染器一律经它；代码评审禁止灰字标题直出。
- **验收**：24 类型截图对照，区块标题视觉一致；无旧样式残留。
- **落点**：P1（组件库）+ P4（全量核查）。

### 3.5 单滚动容器
- **现状**：Tab 外层 ScrollViewer（`EntityEditorView.axaml:24`）+ 每个 visualizer 自带
  内层 ScrollViewer——双层垂直滚动，滚轮事件 / 滚动条 / 惯性手势双重冲突。
- **AF4**：ch12 肢体与视觉负担。
- **JS 设计**：body 唯一垂直滚动；内嵌组件仅允许横向滚动（Encounter 流转三行、图片画廊）。
- **验收**：DOM 检查垂直滚动容器唯一，无嵌套垂直滚动条。
- **落点**：P1（模板定型时天然落地）。

### 3.6 RefPanel 聚合摘要 + 过滤
- **现状**：`BuildReverseRefsPanel` = 类型 tab + 15/页分页 + 平铺行；被 20+ 处引用的实体
  （Faction / Creature / ItemType）答"改了它影响什么"需翻页自查——主要认知负担。
- **AF4**：ch12 认知负担 / ch14 检索按属性而非位置记忆。
- **JS 设计**：快照 `semantics.refs.incoming` 全量已有（D09 §3.1）→
  顶行**聚合摘要**「被 3 个生物 · 5 个物品 · 2 个剧情引用」（类型计数，点击展开该类）→
  组内 IntersectionObserver **滚动加载**（D09 §八.5 懒渲染基础）→ **过滤框**
  （名称 / id 前缀即时过滤）→ 行 hover 预览沿用 Tooltip。
- **验收**：聚合行计数 = incoming 计数；过滤输入即时生效；大引用实体无分页点击。
- **落点**：P2（吸收 D09 既有「反向引用面板」项）。

### 3.7 可感知的可点击性
- **现状**：Ctrl+Click 跳转 / Ctrl+RMB peek 是跨界面习惯用法（一致性很好），但 hover 仅
  cursor 变化，可点击元素可发现性靠试错。
- **AF4**：ch13 顺从与动态提示——丰富的视觉反馈是成功直接操作的关键。
- **JS 设计**：`[data-nav]` 元素统一 hover 态（描边 + 轻微抬升 + cursor）；RefBadge
  静态 `↗` 角标（能供性提示）；tooltip 保留「Ctrl+Click 跳转 / Ctrl+RMB 预览」。
- **验收**：截图 hover 态对照；点击行为与 R15 交互矩阵一致。
- **落点**：P1（组件库）。

### 3.8 薄类型分级（保持薄 = 正确设计）
- **现状**：11 个薄类型 = Hero + stat grid + refs，个别有缺陷（ContainerType 引用
  20 条上限 +N more 无分页无摘要）。
- **AF4**：ch10 简短而完整——薄类型加深是反模式；但薄 ≠ 截断，截断处要能深挖。
- **JS 设计**：分级见 §四；D 级走模板组合**零手写渲染器**；C 级 3 个按问题集轻量增强。
- **验收**：D 级类型渲染 = 组件组合（无 per-type 渲染器代码）；C 级 3 个有专项断言。
- **落点**：P4（D 级 = D09「剩余 21 类型通用渲染器」的定义）+ P1-P2（C 级）。

### 3.9 sticky 段头（长页面导航标志）
- **现状**：长页面（Creature 968 行实现 / ItemType 1484 行）无定位标志，滚动找区块靠记忆。
- **AF4**：ch12 导航标志 / 减少去处。
- **JS 设计**：>3 区块页面 Section 吸顶（sticky top:0 + 毛玻璃底）；可选章节索引条。
- **验收**：滚动时长页面段头吸顶，不遮挡内容。
- **落点**：P4。

## 六、验收要点（可测试断言）

1. **首屏 = Hero**：眯眼测试截图无 Raw Data 干扰（§3.3）；

6. **RefPanel**：聚合行计数 = incoming 计数；过滤即时生效（§3.6）；
7. **D 级零手写**：薄类型渲染 = 组件组合（§3.8）；C 级 3 类型专项断言；
8. **sticky 生效**：>3 区块页面段头吸顶（§3.9）；
9. **回归**：D09 §九 测试不动；Avalonia 层零改动（本设计只约束 JS 版，§〇）。

## 七、设计决策记录

| 决策 | 依据 |
|------|------|
| 审查结论只约束 JS 版，Avalonia 层零改动 | D09 v1.1 已定 P4 下线，不长期双轨（§〇） |
| 修订 21-guide 规则 3（Raw Data 顶部 → 页面底部） | ch17 答案优先；审计入口保留在 TopBar（§3.3） |
| 9 项改进按 D09 阶段吸收，不新开阶段 | 迁移即升级，避免"原样继承 → 返工"（§五） |
