## 〇、用户洞察：单节点无上下文 = 无法认知（v1.1 设计根基）

**"如果看不见一个场景前后的场景，就会很难对场景的流转和定位有一个清晰的认知。
你不知道前一个场景和后一个场景，那么你对这个场景在干什么就会非常疑惑。
从 datatable 来找就着实抽象，因为引用列的复杂语法，基本等于不可能串联。"**

推论（本设计的根基）：
1. **Encounter 的认知单元不是"单个场景"，而是"场景 + 它的前后文"**——前驱（谁通向这里、
   通过什么条件/物品）与后继（我能去哪、代价多少）共同定义这个场景"在干什么"
2. **复杂引用语法（`{item}x{qty}={enc}x{p1}x{p2}x{p3}x{p4}`）必须由 UI 翻译**为直观的
   流转标注（物品图标+名称、条件语义色、概率百分比），绝不让用户读原始语法
3. **流转视图必须常驻主视图**（默认可见前后各一层），不能藏在 Tab 或列表里

## 一、定位转变：从「字段分区」到「剧情节点工作台」

**Encounter 是唯一一种本身就是「图」的数据类型**——`aResponses` 就是剧情图的边，
2264 个 Encounter 构成一张剧情流图。因此 Encounter 页面的信息架构不应是
「Hero / 文本 / 分支 / Refs / 触发器 / 被引用」的字段分区，而应是**一个剧情节点的完整画像**：

| 段 | mod 开发者的问题 | 数据来源 | 现状 |
|----|-----------------|---------|------|
| ① 身份 | 这是什么剧情 | strName/strImg/nType + 入口/终点标记 | ✅ Hero 基本有，缺入口/终点标记 |
| ② **场景流转**（v1.1 一等公民）| **前后场景是什么、如何流转** | 前驱（aResponses 反查）+ 当前 + 后继（D06/D07 分支）| ❌ 前驱被塞底部列表、后继单层无前后文 |
| ③ 如何进入 | 什么情况下会出现 | aConditions + EncounterTrigger 反查 | ❌ 散在 Refs/触发器 |
| ④ 内容与效果 | 进去后发生了什么 | strDesc + vLoot/nItemsID/fPrice/nRemoveTreasureID/ptTeleport/nCreatureID | ❌ **效果无聚合** |
| ⑤ 剧情链位置 | 在整条剧情链什么位置 | 链树 Tab | 🟡 样式落后，流转主视图已覆盖核心认知 |

**核心变化**：**场景流转成为主视图**（②，默认前后各一层、双向可导航），Refs 面板拆散归位，新增「效果」聚合区。

**流转主视图规格（v1.1 核心）**：

| 部件 | 规格 | 说明 |
|------|------|------|
| 结构 | **三行布局**（R64）：行1 前驱层（横向排开）→ 行2 当前场景（居中）→ 行3 后继层（横向排开），整体横向 ScrollViewer | 每层内部横向一字排开（一屏多节点），当前场景独立第二行居中——不是全部塞进同一行（那样更放不全） |
| 前驱节点 | 复用 `BuildEncounterNodeCard`（无概率胶囊，有 `←` 来路标注）| 卡片显示来路触发：`🛡 撬棍 →` / `需同时拥有 A+B`（D07 语义复用）|
| 前驱→当前 连线 | 箭头 + 来路标注（该前驱的哪条响应通向当前：物品/条件/概率）| **引用语法全翻译**：`90.1x1=12x1x0x0x0` → `🛡 撬棍 ×1 →` |
| 当前卡 | 现有 `BuildEncounterNodeCard`（IsCurrent，高亮 + 📍）| 不接导航 |
| 后继层 | D06/D07 分支卡复用（概率胶囊/终止胶囊/AND/p2·p3 全部保留）| 不改渲染，只改容器 |
| 深度 | **前驱默认 1 层、后继默认 1 层**（用户认知最小单元）| 点击前驱卡可"进入"该场景继续展开（导航即展开）|
| 无前驱 | 左侧显示 `⛳ 入口` 徽章（无入边）| 与 Hero 入口标记一致 |
| 无后继 | 右侧显示 `⏹ 终点` 徽章（全终止出边）| 与 Hero 终点标记一致 |
| **回到当前场景**（v1.2→v1.3）| 流转视图节标题右侧 `⏎ 回到当前` 按钮（9px 小按钮，`#E3F2FD/#1565C0`）| **v1.3：组件内焦点复位**（`current = enc; RebuildFlow()`），不再页面跳转——配合左键点击导航，浏览任意深度后一键回到最初场景 |
| **左键点击导航**（v1.3）| 前驱卡与后继卡（EndKind.None）普通左键点击 | **组件内焦点切换**：`current = 目标; RebuildFlow()`——重算该场景的入边/出边并重渲染，组件内漫游剧情流（用户澄清原意图）；「回到当前」复位 |
| **节点修饰键导航**（v1.2）| 前驱卡与后继卡整卡挂 `_refNode.WireNavigation`（`RefNode.cs:116` 已内置）| **Ctrl+LMB = 页面跳转到该场景**；**Ctrl+RMB = Peek 预览**（v1.3 修复：解析目标实体而非 sourceEntity——此前 peek 显示当前实体）；当前卡不接导航 |

**设计原因**：这是对用户洞察的直接回答——「前后场景」成为常驻主视图，DataTable 的复杂
引用语法（`90.1x1=12x1x0x0x0`、`91.8x1+91.3x1=22`）全部由 UI 翻译成「🛡 物品 → 场景」的
直观流转标注。前驱用与后继完全相同的节点卡语言，视觉对称，一眼理解"我是谁、从哪来、到哪去"。

**与底部被引用面板的职责边界**（避免"重复"反馈）：流转主视图 = **Encounter 类型内**的
剧情流转语义视图（只显示 aResponses 指向本场景的 Encounter，带来路标注）；底部面板 =
**全类型**被引用审计（含 Recipe/TreasureTable 等其他来源，列表分页）——两者并存，
前者是"剧情上下文"，后者是"数据审计兜底"。

## 三、① 身份（Hero 升级）

**保留**（现状）：

**新增**：

  - 与流转主视图的入口/终点徽章同源（同一判定函数）

## 四、③ 如何进入（条件/触发器详情）

### 4.1 触发条件（aConditions）
- 现状：Refs 面板一行徽章（`Vis.Conditions` 节，126 行区域）
- 新：本段首行「触发条件」——徽章行（语义色：Fatal红/Instant橙/Stackable绿/时长蓝，hover 条件效果翻译）
- 数据：2189/2264 有值，但 1116 条是 "1"（无条件占位）→ **"1" 和 "0" 不显示**（去噪，少呈现）

### 4.2 触发器摘要（EncounterTrigger 反查）
- 现状：`BuildTriggersPanel`（FindTriggers 反查）在 Hero 之下单独一节，只显示名称徽章
- 新：并入本段——每行 `名称 + 触发方式摘要`：
  - `aArea` 非空 → `📍 ({x},{y},r={dist})`
  - `dateMin/dateMax` → `📅 {min}~{max}`
  - `aHexTypes` 非空 → `🧱 格类型`
  - `bUnique` → `♻ 可重复`（1=唯一不显示）
  - 可跳转 EncounterTrigger

**设计原因**：mod 开发者调"这个剧情不触发"时，先看 ③——条件对不对、触发器有没有。
（入边已由 ② 流转主视图承担——前驱节点卡直接可见，不再在此重复）

## 五、④ 内容与效果（核心新增）

### 5.1 描述（书页式）
- 现状：BuildStoryPanel 描述平铺 2000 截断
- 新：图+文并排——左 96px 缩略图（strImg，点击放大）+ 右描述文本；描述为空隐藏整段

### 5.2 ✨ 效果区（聚合行，本设计核心）

**把 6 个"副作用"字段聚合成行为行**，每行 = `图标 + 语义 + 数据`：

| 字段 | 条件（非空才显示） | 行 | 配色 |
|------|-------------------|-----|------|
| vLoot | ≠"0" 且 ≠"3"（空白池哨兵，D07 v1.2） | `🎁 给物：{池名}` + 内联战利品树（复用 TreasureTable 树，概率归一） | 绿 #2E7D32 |
| nItemsID | ≠"3"（默认哨兵） | `📦 给予物品：{物品名}`（可跳转 ItemType） | 蓝 #1565C0 |
| fPrice | ≠0 | `💰 费用：{$N}`（实测全正=扣钱，41 条） | 紫 #6A1B9A |
| nRemoveTreasureID | ≠"3" | `🗑 移除：{池名}`（可跳转） | 红 #C62828 |
| ptTeleport | ≠"0,0" | `📍 传送：({x},{y})` | 青 #00695C |
| nCreatureID | ≠"0" | `🐾 刷出：{生物名}（半径 {hex}）`（ptCreatureHex 非 "0,0" 才显示半径） | 橙 #E65100 |
| aConditions（效果链） | 非无条件且指向 Condition 带 aEffects | `⚡ 效果：{效果翻译}`（hover，复用 R43 条件效果翻译） | 灰 #546E7A |

- 无任何效果 → 整段隐藏（少呈现）
- 每行 = `MiniBadge` 风格 + 可跳转实体走 `_refNode`
- **设计原因**：这 6 个字段是"这个剧情做了什么"的完整答案，现在散在 Refs 面板各行
  （vLoot 一行、nItemsID 一行、fPrice 在 Hero 概率行…），mod 开发者无法一眼看到剧情行为

### 5.3 Refs 面板拆散后的归宿

| 原 Refs 节 | 去向 |
|-----------|------|
| Conditions（aConditions） | → ③ 如何进入·触发条件 |
| PreConditions | → ③ 如何进入（当前剧情自己的前置条件，放在触发条件旁） |
| TreasureId / RemoveTreasureId | → ④ 效果区（给物/移除） |
| ItemsId | → ④ 效果区（给予物品） |
| Loot（vLoot） | → ④ 效果区（给物） |
| CreatureId + CreatureHex | → ④ 效果区（刷出） |
| Teleport | → ④ 效果区（传送） |
| Accidents | → ④ 效果区（搜刮事故引用，保留徽章行） |
| **aMinimapHexes / ptEditor** | **保留在独立小节**（R57 加的；小地图标记不是"效果"，是"地图标注"——放 ④ 底部小节「地图标注」，或保留为 Refs 剩余节） |
| **aResponses** | 已在流转主视图（②） |

> 若某些节无处可归或语义弱（如 Accidents），**保留在页面底部「其他引用」折叠区**，不硬塞。
