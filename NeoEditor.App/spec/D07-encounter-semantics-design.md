## 二、升级范围与原则

**范围**（按数据量/价值排序，全部围绕分支数据语义）：
1. **终止节点语义**（F1+F2，~1292 段受影响）——分支图最大头
2. **Ingredient 双目标解析**（F3）——最常见触发物从 `Item #52` 变 "撬棍"
3. **tooltip 补 p2/p3 语义**（F4+F5）——销毁标记与成功概率
4. **AND 多物品语义**（F6）——"同时拥有"不丢失
5. **vLoot/nItemsID 用途标注**（F7+F8）——Refs 面板小改

**原则**（用户提醒）：
- 每个呈现决策必须有数据依据；**不做没有数据支撑的 UI**
- 宁可少呈现，不误导——终止节点不该画成"分支卡"，Unknown 不该显示成有意义的物品
- 呈现顺序 = 用户读剧情的顺序：**结局状态 → 触发方式 → 触发代价**

## 三、1. 终止节点语义（F1+F2）

### 3.1 语义判定（纯函数）

```csharp
enum BranchEndKind { None, Stay, Blank }
// None   = 正常分支（指向真实 Encounter）
// Stay   = 自指（TargetId == 当前 Encounter.Id）→ 「⏹ 停留原地」
// Blank  = 指向 id=1（Blank 空剧情）→ 「☰ 无后续」
```

- 判定基于 `BranchData.TargetId` 与当前 `enc.Id` 的关系（纯数据，不依赖 UI）
- **注意**：id=1 的 Encounter 自身在数据中是"Blank"（空描述、自指）——若用户**正在查看 id=1**，它显示为普通剧情（自指规则优先，Stay 而非 Blank）

### 3.2 呈现（分支图）

| 类型 | 渲染 | 说明 |
|------|------|------|
| None（正常） | 现有节点卡（图片+标题+概率+chip） | 不变 |
| Stay（自指） | **终止标记**：灰色圆角胶囊 `⏹ 停留`（10px，#ECEFF1/#546E7A），替换卡片；概率仍显示（`停留 100%`） | 不是一张卡——没有目标可跳转，画卡是误导；胶囊表达"剧情在此停留/结束" |
| Blank（无后续） | **终止标记**：灰色圆角胶囊 `☰ 无后续`（同配色），替换卡片；概率仍显示 | 指向 Blank 没有信息增量（Blank 永远是空剧情），胶囊足够 |

**设计原因**：分支图的职责是"这个剧情选项会通向哪"——通向"停留"和"无后续"都是**终点**，不是分支。终点用与分支卡完全不同的视觉形态（胶囊 vs 卡片），用户一眼区分"还有路走 / 到此为止"。这是 F1+F2 的数据语义最自然的呈现。

**Mermaid 同步**：自指段输出 `A --> A` 改为注释行或 `A -->|"停留(100%)"| A_stay["⏹ 停留"]`；Blank 段输出 `A -->|"权重(概率)"| BLANK["☰ 无后续"]`（与图形一致）。

### 3.3 tooltip（终止段）
- Stay/Blank 段仍可 hover：显示权重/有效概率行（信息量少，无物品/条件可显示）
- 不挂导航（没有真实目标）

## 四、2. Ingredient 双目标解析（F3）

### 4.1 解析规则（改 `ParseResponseEntries` 的 itemId 分支）

```
itemId 格式判定：
  含 '.'  → ItemType G.S 复合键（90.3、91.8）   → LookupRef<ItemType>（现状）
  纯数字  → Ingredient nID（52、49、47、78、83、115）→ LookupRef<Ingredient>（新增）
  空      → 默认回应（无物品）
```

- 纯数字优先查 Ingredient（Doc 37 §5.1 已验证 6 种）；查不到再尝试 ItemType 主键（兜底，防 mod 用纯数字 id 引用 ItemType——`encounters.nItemsID` 就是 ItemType 主键 id 格式，但那是另一个字段；此处保持 Ingredient 优先 + ItemType 兜底）
- `BranchItem` 增加 `Ingredient? Ing` 字段（解析结果）
- 解析不到 → 现有灰色 `Item #{id}` 兜底（不崩溃）

### 4.2 呈现
- tooltip 物品行：Ingredient 徽章用 `🛠 {Ing.Name}{×qty}`（工具色 `#E8EAF6/#283593`，与 ItemType 的 `🛡 #E3F2FD/#1565C0` 区分——**材质工具 vs 物品**）
- 徽章可跳转 Ingredient（`_refNode.BadgeForEntity` 支持）

**设计原因**：`52=撬棍` 是响应中最常见的触发物之一，显示 `Item #52` 是纯噪音。Ingredient 是"材料/工具"语义（撬棍、透镜、剪线钳），用工具图标+色系与物品区分，用户一眼知道"这是工具"。

## 五、3. tooltip 补 p2/p3 语义（F4+F5）

### 5.1 数据模型扩展

`BranchItem` 增加：`bool DestroyOnUse`（p2=1）、`double SuccessProb`（p3，默认 1.0）
`BranchData` 增加：`double? SuccessProb`（取 Items 中非 1.0 的 p3；多物品取最大非 1 值；全 1 则 null）

### 5.2 呈现（tooltip 信息卡）

| 语义 | 显示 | 依据 |
|------|------|------|
| p2=1 销毁 | 物品徽章后缀 `（消耗）`：`🛡 撬棍 ×2（消耗）` | F4：32 段由回应直接销毁 |
| p2=0 | 不显示（无额外语义，由目标移除池处理——少呈现） | F4：54 段，语义由目标承担 |
| p3<1 成功概率 | 独立行：`⚡ 成功概率 50%`（橙 #E65100） | F5：破解场景 50%/必成功 |
| p3∈(0,1) | 独立行：`⚡ 成功概率 50%`（橙 #E65100） | F5：破解场景 9 段（0.1×3/0.5×5/0.2×1） |
| p3=0 / p3=1 | **均不显示** | 实测 p3=0 占 99.1%（4351/4392，标准后缀默认值），p3=1 仅 32 段（必成功无信息量）；v1.1 修正——按字面 p3<1 会误标 99% 分支为 0% 成功 |

**不做的**：p2=0 时去查目标 nRemoveTreasureID 并列出移除池——那是目标剧情的职责，tooltip 只回答"这个选项的代价"（消耗与否、成功与否）。

## 六、4. AND 多物品语义（F6）

### 6.1 解析
- 响应段左侧 `+` 分隔多个 itemRef：`91.8x1+91.3x1=22` → 该段的 `BranchItem` 列表标记 `IsAnd = true`
- `BranchItem` 增加 `bool IsAnd`（默认 false；同一段内除第一个外全部 true，或段级标记）

### 6.2 呈现（tooltip）
- AND 段：物品徽章间用 **`+` 连接符** + 前缀 `需同时拥有：`——`需同时拥有：🛡 技能A + 🛡 技能B`
- 非 AND（多段同目标合并）：保持现有并列徽章（`🛡 撬棍 ×2`、`🛡 打火机` 各自独立行）——两者语义不同：**"都要" vs "任一"**

**设计原因**：`91.8x1+91.3x1=22` 的语义是"必须同时有两个技能"，与"撬棍或打火机都能触发"完全不同。并列徽章让用户以为二选一，是误导。`+` 连接 + 前缀是数学直觉（AND 符号），学习成本最低。

## 七、5. vLoot / nItemsID 用途标注（F7+F8）

### 7.1 Refs 面板小改（`BuildRefsPanel`）
- `vLoot` 节：标签按 type 区分——`nType==1`（搜刮）→ `搜刮池`；否则 → `事件给物`（569/598 是普通剧情给物，这是主语义）
- `nItemsID` 节（487 条非默认）：标签 `触发给予物品` + tooltip 显示物品名（现状只有徽章；挂 `BuildRefTooltip` 或直接名称）

### 7.2 不改的
- `fLootChance/fAccidentChance/fCreatureChance` 已进 Hero 概率行（R57）——保持
- `aConditions`（本剧情条件）在 Refs 面板——保持（分支 tooltip 的 PreConds 是目标条件，职责已分清 F9）

## 九、设计决策记录

| 决策 | 依据 |
|------|------|
| 自指/Blank → 终止胶囊而非卡片 | F1+F2（437+855 段）；分支图职责是"通向哪"，终点不是分支；画卡是误导 |
| 纯数字 → Ingredient 优先 + ItemType 兜底 | F3（Doc 37 §5.1 六种已验证）；纯数字也有可能是 mod 的 ItemType 主键 |
| p2=1 才显示"消耗"，p2=0 不显示 | F4（32 vs 54）；少呈现原则——p2=0 的移除语义在目标剧情 |
| p3<1 才显示成功概率 | F5；默认 1.0 去噪 |
| AND 用 `+` 连接 + 前缀 | F6（5 段）；与"任一"并列语义区分，数学直觉零学习成本 |
| vLoot 按 type 标注用途 | F7（569/598 是普通剧情给物，主语义是给物不是搜刮） |
| nItemsID 提级显示 | F8（487 条高频） |
| aConditions 不进分支 tooltip | F9（职责已分清，现状正确） |

## 十、验收要点（可测试断言）

1. **终止判定纯函数**：`PrepareBranches` 对自指段（`=Nx1x0x0x0` 且 N==当前 id）输出 `EndKind=Stay`；对 `=1x1x0x0x0` 且当前 id≠1 输出 `EndKind=Blank`；正常段 `None`——纯数据断言，不依赖 UI
2. **终止渲染**：Stay/Blank 分支渲染为胶囊（MiniBadge 含 "⏹ 停留" / "☰ 无后续" 文本）而非卡片；无 Image、无标题卡、无导航
3. **Mermaid 同步**：Stay → `停留` 节点；Blank → `☰ 无后续` 节点；不出现自环箭头 `A --> A`
4. **Ingredient 解析**：`52x1=16x1x0x0x0` 且 resolver 有 Ingredient#52（撬棍）→ `BranchItem.Ing` 非空、`Item` 为 null；tooltip 含 `🛠 撬棍`（工具色系）
5. **兜底**：纯数字查不到 Ingredient 且查不到 ItemType → 灰色 `Item #{id}` 不崩溃
6. **p2 消耗**：`49x1=930x1x1x1x0`（p2=1）→ tooltip 物品徽章含 `（消耗）`；p2=0 无后缀
7. **p3 成功概率**：`8.7x1=1088x1x0x0.5x0` → tooltip 含 `成功概率 50%`；p3=1 不显示
8. **AND 语义**：`91.8x1+91.3x1=22` → tooltip 含 `需同时拥有` 且两徽章间有 `+`；多段同目标合并（`90.3x2=16x2x0x0x0,=16x1x0x0x0`）仍为并列（无 `需同时拥有`）
9. **vLoot 标注**：type=1 → Refs 面板 `搜刮池`；type=0 → `事件给物`
10. **nItemsID 提级**：非 3 的 nItemsID → Refs 面板 `触发给予物品` 节显示物品名
11. **回归**：现有 16 个 EncounterVisualizerTests 全绿；862 全量无回归
