# 本轮迭代：MCP 薄弱点完善 + Search 增强

## 一、基础修复（薄弱点）

### 1. 字段级 GetDiff（替换占位实现）
- **`NeoEditor.Infra/Data/Repository/DiffEngine.cs`**：`ComputeDiff` 对带 `[ReferenceField]` 的属性改用 `ReferenceText.GetRawString`（Core/Model/ReferenceText.cs）规范化后比较/序列化，避免 `ReferenceList.ToString()` 的损坏格式（"[16, 46]"）导致误报
- **`NeoEditor.Infra/Services/HostService.cs` `GetDiffAsync`**：对每个 dirty id 取缓存版本（`_entityCache`）+ DB 版本（现有 `FindEntityInDbSet`），调 `DiffEngine.ComputeDiff(dbVersion, cachedVersion)`（泛型推导为 IEntity，运行时取实际类型，无需反射）→ 产出真实字段级 Modified/Added（DB 无记录）/Removed（缓存无记录=已删除未保存）列表
- 现有 `DiffEntry` 字段不变，UI/CLI 消费方兼容

### 2. Save 工具回传真实结果
- **`EditorTools.Save`**：记录调用前 dirty 数量，返回 `SaveResult.SavedEntityIds` 列表、保存数量、剩余 dirty 数量（覆盖"dirty 但不在缓存→跳过"的 cache-miss 分支，不再报 `{saved:true}` 假成功）

### 3. 修复双重执行 bug
- **`HostService.ExecuteAsync`/`ExecuteBatchAsync`**：当前 `command.Execute()` + `scope.Execute(command)`（内部再执行一次）= 双重执行。改为：scope 存在时只调 `scope.Execute(command)`（内部执行+压栈），否则手动 `command.Execute()`；`ApplyCacheDelta` 保持在执行后
- 回归测试：`AddEntityCommand` 带集合回调 → 集合只插入一次；Undo/Redo 行为不变

## 二、Search 增强（自定义过滤 + 选表 + 分页 + 排序）

### 4. Core 新类型 + 接口方法
- **新文件 `NeoEditor.Core/Abstractions/EntitySearch.cs`**：
  - `enum FilterOperator { Contains, Equals, NotEquals, StartsWith, EndsWith, GreaterThan, GreaterThanOrEqual, LessThan, LessThanOrEqual }`
  - `record EntityFilter(string Field, FilterOperator Operator, string Value)`
  - `record EntitySearchRequest(string Query, IReadOnlyList<string>? EntityTypes, int? ModId, IReadOnlyList<EntityFilter>? Filters, int Limit, int Offset, string? SortBy, bool SortDescending)`
  - `record EntitySearchResult(IReadOnlyList<IEntity> Items, int Total, bool Truncated)`（Total=分页前过滤总数）
- **`IHostService`**：新增 `Task<EntitySearchResult> SearchEntitiesAsync(EntitySearchRequest request)`，**带默认接口实现**（C# 11，.NET 10 支持）委托旧 4 参方法（EntityTypes 取首个、忽略 Filters/SortBy、Total=Count）→ 6 个测试桩零改动；旧签名保留，生产 `HostService` override 全功能实现

### 5. HostService 实现
- 目标类型集合：`EntityTypes` 或全部（`Constants.GameTypes`）；modId 过滤；query 全文匹配（Subject/ID/字符串属性，沿用现有 `MatchesQuery` 逻辑）
- 过滤器：复用 `FilterService.FindColumnProperty`（Infra 内静态，列名/属性名大小写不敏感）；类型化比较 helper：string（contains/equals/startsWith/endsWith，OrdinalIgnoreCase）、数值（int/long/double/float/decimal TryParse 后大小比较）、bool、enum（名字或数值）、引用字段（raw text）、其余 ToString 回退；AND 语义
- 排序：`SortBy` 字段类型化 `IComparable` 比较，null 排后，`SortDescending` 控制方向
- 分页：`Total` = 过滤后总数；`Items = Skip(Offset).Take(Limit)`；`Truncated = Offset + Limit < Total`

### 6. MCP SearchAllTypes 改造
- 新增可选参数：`entityTypesJson`（`["ItemType","Creature"]`）、`filtersJson`（`[{"field":"Weight","op":">=","value":"1.5"}]`，op 字符串→FilterOperator 映射含 `>=,<=,>,<,==,=,!=,<>,contains,startsWith,endsWith,notEquals`）、`offset`；保留 query/entityType/modId/limit 兼容
- 返回增加 `total`/`offset`/`truncated`；JSON 解析失败返回 error

## 三、新增 MCP 工具（机制已有，只缺协议面）

`EditorTools` 新增 4 个（工具总数 12→15）：
- `Undo()` / `Redo()`：`_hostService.UndoAsync("mcp")` / `RedoAsync("mcp")`，返回成功 + 当前 dirty 数
- `Publish(commit: bool = false)`：`PublishAsync()`（SaveAll + Export 预览），`commit=true` 时对全部 RowDiff 调 `CommitExportAsync` 写文件；返回保存数 + 各 mod 导出文件摘要（TargetId/Kind，内容截断）
- `ExportMod(modId, commit: bool = false)`：`ExportModAsync(modId)` 预览，可选直接 `CommitExportAsync`（对齐 UI 流程：预览→确认→写文件）
