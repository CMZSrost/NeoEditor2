## 目标
- 建 `NeoEditor`、`NeoPlayer` 两条产品线分支；打 tag 自动经 GitHub Actions 发包（版本取 tag，DLL/exe 带版本）
- workflow 内置**可选签名步骤**（Rider 签名留给你本地自用，两不冲突）
- 交付「workflow 签名 + 免费证书方案」教程

## 现状（已确认）
- 远程 `github.com/CMZSrost/NeoEditor2`，只有 `main`；已有 release.yml（`v*` 触发、publish NeoEditor.App、无版本注入）
- 所有 csproj 无版本属性 → publish 时用 `-p:Version/-p:AssemblyVersion/-p:FileVersion/-p:InformationalVersion` 注入，全图程序集自动带版本，零代码改动
- 决策已确认：NeoPlayer 分支构建现有 `NeoEditor.Player`（NeoScavengerPlayer）；tag 用前缀区分（`NeoEditor-v*` / `NeoPlayer-v*`，tag 全仓库唯一防撞车；GitHub 对 tag push 用 tag 指向提交里的 workflow，天然按分支隔离）

## 实施步骤
1. `git switch -c NeoEditor` / `git switch -c NeoPlayer`（均从 main HEAD；工作区未提交改动不动，每分支只提交 workflow 文件）
2. **NeoEditor 分支**改造 `.github/workflows/release.yml`：
   - 触发 `NeoEditor-v*`；pwsh 剥离前缀得版本（预发布后缀 `-xxx` 拆出，AssemblyVersion 只用数字段）
   - publish NeoEditor.App（沿用现有参数）+ 注入 4 个版本属性
   - **可选签名步骤**：若配置了 `SIGN_PFX_BASE64`/`SIGN_PFX_PASSWORD` secret → 解码 PFX → 用 windows-latest 自带的 signtool.exe 对 exe/dll 做 SHA256 + RFC3161 时间戳签名；未配置则打印跳过并正常出包
   - 产物 `NeoEditor-<版本>-win-x64.zip`，Release 名 `NeoEditor <版本>`
3. **NeoPlayer 分支**改写 `.github/workflows/release.yml`：同结构，触发 `NeoPlayer-v*`，构建 `NeoEditor.Player/NeoEditor.Player.csproj`，产物 `NeoPlayer-<版本>-win-x64.zip`，Release 名 `NeoPlayer <版本>`，同样可选签名
4. 各分支提交 workflow 并 `git push -u origin NeoEditor NeoPlayer`（main 原样不动）
5. **验证**：本地两个项目各跑一次 `dotnet publish -r win-x64` 冒烟测试 + YAML 检查；打 tag 触发发包的测试步骤写进交付说明（tag 由你决定何时打，我不代打）
6. **教程交付**（聊天内，含可复制命令）：
   - 方法一（免费，立即可用）：自签证书 + signtool —— New-SelfSignedCertificate 生成、导出 PFX、base64 存 secret、workflow 签名片段；SmartScreen 对自签新发布者会拦截，适合内部/测试分发
   - 方法二（推荐公开分发，~$9.99/月 5千次签名）：Azure Artifact Signing（原 Trusted Signing，无免费档，公信链但新发布者同样有 SmartScreen 声誉积累期）—— 官方 `azure/artifact-signing-action@v2` + OIDC 配置全流程
   - 方法三（开源免费）：SignPath Foundation（OV 级证书，需开源+审核）
   - 备选：Microsoft Store MSIX 免费重签（唯一无警告的免费路）、macOS ad-hoc `codesign -s -`（免费）/ notarization 需 $99/年、.NET 强命名（免费但与信任无关）
   - 你本地用 Rider 签名不受影响（Rider 插件内部走的也是 Azure Trusted Signing 同款 API，workflow 用官方 action 效果一致）
