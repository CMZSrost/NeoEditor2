# 仅产出计划文档（不实施任何功能代码）

## 交付物
写一份计划文档到 `NeoEditor.App/Docs/41-webview-ruffle-preview-plan.md`（与现有 `Docs/40-ruffle-game-runner-plan.md` 并列，格式对齐 Docs/40 的中文结构化风格），内容为本次调研的全部结论与实施规划：

1. **背景与目标**：新增 WebView 工具面板模块（Avalonia.Controls.WebView 12.0.1 官方控件，Avalonia 12 重新开源版），内置 Ruffle Web（WASM Flash 模拟器）快速预览游戏 SWF；与现有 ruffle.exe 运行器（Docs/40）并存互补。
2. **调研结论（可行性分析）**：
   - Avalonia.Controls.WebView 12.0.1：官方包确认（net8.0/net10.0，Windows 走系统 WebView2 Runtime，无 TFM 改动）
   - Ruffle Web：self-hosted WASM 包（ruffle.js + ruffle-wasm/），MIT/Apache-2.0 可随包分发，player.load({url}) API
   - SWF 提供方式：file:// 被 Chromium 拦截 → 回环 HTTP 服务（HttpListener 127.0.0.1 随机端口，{gameRoot} 挂根，data//img/ 相对路径与 --base file:/// 语义一致）
   - 代码复用点：RuffleOptionsBuilder.FindSwfPath、插件模式（IToolPlugin + AddXxxPlugin）、GameRootDir 配置
   - ⚠️ 高风险：游戏 SWF 以 --player-runtime air 运行（AIR 目标），web 版 Ruffle 只有 Flash runtime → 快速预览定位，完整游戏仍走 ruffle.exe
3. **总体设计**：新插件 NeoEditor.Plugins.WebView（插件骨架、WebView 面板、GameContentServer、host.html、JS console 桥接）
4. **实施阶段**：Phase 0 验证（0.1 Ruffle web 实跑 SWF / 0.2 控件验证 / 0.3 定案）→ Phase 1 通用 WebView 面板 → Phase 2 Ruffle 集成 → Phase 3 文档与测试
5. **风险登记**：R1-R5（AIR API、控件 API 面、WebView2 Runtime 缺失、回环服务安全、资源体积）
6. **验收与开放问题**
